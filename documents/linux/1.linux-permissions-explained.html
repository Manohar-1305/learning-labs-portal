Linux Permissions Explained

Linux administration | File ownership | Access control | Security

1. What Are Linux Permissions?

Linux permissions control who can read, modify, and execute files and directories. They protect system files, application data, configuration files, scripts, and user information from unauthorized access.

Every file and directory has an owner, an associated group, and permission settings. 

ls -l /etc/passwd

-rw-r--r-- 1 root root 2847 /etc/passwd

2. Linux Permission Categories

Linux uses three permission categories:

CategorySymbolDescription
OwneruThe user who owns the file
GroupgUsers belonging to the file's group
OthersoAll other users

3. Permission Types

Directory permissions behave differently from file permissions. For example, execute permission on a directory allows a user to traverse it, even if the user cannot list its contents.

4. Understanding Numeric Permissions

Numeric permissions are calculated by adding permission values.

Read    = 4
Write   = 2
Execute = 1

7 = 4 + 2 + 1 = rwx
6 = 4 + 2     = rw-
5 = 4     + 1 = r-x
4 = 4         = r--
3 =     2 + 1 = -wx
2 =     2     = -w-
1 =         1 = --x
0             = ---

Example: chmod 755

chmod 755 deploy.sh

5. chmod - Change File Permissions

The chmod command changes permissions on files and directories.

Numeric Method

chmod 755 deploy.sh
chmod 644 application.conf
chmod 700 /opt/application/secrets

Symbolic Method

chmod u+x deploy.sh
chmod g+w shared.txt
chmod o-r confidential.txt
chmod u=rwx,g=rx,o= file.sh

Recursive Permissions

chmod -R 755 /opt/application
Avoid blindly applying one permission to every file and directory. Executable files, regular files, and directories often need different permissions.

6. chown - Change Ownership

Use chown to change the owner or group associated with a file.

# Change owner
sudo chown appuser application.log

# Change owner and group
sudo chown appuser:appgroup application.log

# Change only group
sudo chown :appgroup application.log

# Change ownership recursively
sudo chown -R appuser:appgroup /opt/application

7. chgrp - Change Group Ownership

sudo chgrp developers project.txt

sudo chgrp -R developers /opt/project

Use chgrp when only the group ownership needs to change.

8. Directory Permissions Explained

Directory permissions determine what users can do inside a directory.

PermissionEffect
rList directory entries
wCreate, delete, and rename entries, subject to other permission rules

mkdir project
chmod 750 project
ls -ld project

9. umask - Default Permission Mask

umask controls which permission bits are removed from the default permissions when new files and directories are created. 

# Check current umask
umask

# Set umask
umask 022

# Create test objects
touch test-file
mkdir test-directory

# Verify
ls -l test-file
ls -ld test-directory
ObjectBase PermissionWith umask 022
Regular file666644
Directory777755

A regular file is normally created without execute permission. The resulting permissions can also be affected by the application creating the file.

10. Special Permissions

SUID - Set User ID

On an executable file, SUID causes the program to run with the effective user ID of the file owner. 

ls -l /usr/bin/passwd
chmod u+s program

SGID - Set Group ID

On an executable file, SGID sets the effective group ID for the process. On a directory, newly created entries generally inherit the directory's group. 

chmod g+s shared-directory
ls -ld shared-directory

Sticky Bit

On a directory, the sticky bit restricts deletion and renaming of entries, typically allowing only the entry owner, directory owner, or a privileged user to do so. 

chmod +t /shared
ls -ld /shared

11. Access Control Lists (ACL)

ACLs provide additional permissions for specific users and groups beyond the traditional owner, group, and others permission model. 

# View ACL
getfacl project.txt

# Grant a user read and write access
setfacl -m u:developer:rw project.txt

# Grant a group read access
setfacl -m g:developers:r project.txt

# Remove a user's ACL entry
setfacl -x u:developer project.txt

# Remove extended ACL entries
setfacl -b project.txt
The ACL mask can limit the effective permissions of named users, named groups, and the owning group. Use getfacl to inspect effective access.

12. Troubleshooting Permission Issues

Useful commands for investigating permission problems:

# View permissions
ls -l file.txt

# View directory permissions
ls -ld /opt/application

# Inspect every directory in a path
namei -l /opt/application/config/settings.conf

# Check current user
whoami

# Check group membership
id

# Check ACL
getfacl file.txt

# Check ownership
stat file.txt

# Test whether a user can read a file
sudo -u appuser test -r file.txt && echo "Readable" || echo "Not readable"

# Test whether a user can write to a directory
sudo -u appuser test -w /var/log/application && echo "Writable" || echo "Not writable"

13. Production Security Guidelines

  • Do not use chmod 777 as a routine permission fix.
  • Run services with dedicated non-root users where practical.
  • Keep private keys and credentials restricted.
  • Use group ownership for controlled shared access.
  • Inspect parent directory permissions when access fails.
  • Use ACLs when standard owner/group permissions are insufficient.
  • Verify permissions after deployments and container volume mounts.
  • Apply least-privilege access to application directories.
